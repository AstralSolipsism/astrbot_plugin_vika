# Write Safety

Write tools use preview/commit. They do not execute directly.

Write plans are runtime-scoped. A preview generated by one server/runtime
instance cannot be committed through another instance.

Preview returns a stable write plan for the model:

- `operation_id`
- `operation_type`
- `datasheet_id`
- `target_label`
- `record_count`
- `validation_summary`
- `risk_level`
- `payload_hash`
- `expires_at`
- `confirmation_context`
- `confirmation_brief`
- `ask_user_instruction`

The model must use `confirmation_context` and `confirmation_brief` as facts, then ask the user for confirmation in one natural-language sentence. Do not show raw payload, sample records, complete field lists, or debug-shaped JSON to the user.

Commit requires:

- `operation_id`
- `confirmed_payload_hash`, exactly equal to preview `payload_hash`
- `confirmed_by_user=true`
- optional `user_confirmation_summary` for audit only

The service rejects missing user confirmation, missing or mismatched payload hash, expired operations, and mutated stored payloads. Repeated commits return `already_committed` with the original result.

Attachment upload keeps arbitrary local `file_path` support. It does not impose
an artifact-root or workspace path restriction. Preview records and exposes the
file facts needed for confirmation:

- `file_path`
- `file_name`
- `file_size_bytes`
- `file_sha256`

Commit recalculates size and SHA-256 before calling Vika. If the file was
replaced or modified after preview, commit returns `file_hash_mismatch` and does
not upload.

Direct MCP write payload limits:

- max 500 records
- max serialized payload 1 MB

Larger imports must be staged as artifacts before preview.
